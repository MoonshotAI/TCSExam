# Sanity fixture — ramsey-r46-lean

This fixture is a small submission that the judge should accept (N=14, below the scoring baseline), used to check the scoring path.

`Basic.lean` is a complete submission: the fixed layer plus a Lean coloring obtained by taking the induced subgraph on vertices 0..13 of the N=24 baseline graph bundled with the ramsey-r46 Solver sibling (`environment/examples/example_n24.json`). The graph was generated by the deterministic starter `local_search.py 24 1`; the induced subgraph remains (4,6)-free and has 37 red edges. After the `powersetCard` bridge, `submission_lower` is proved by two `by native_decide` steps. `submission_upper` is left with `sorry` to check that leaving one side incomplete does not affect the other side.

Expected result (default `solver_cubic` mode): reward = 0.0 (N=14 ≤ 24 is below baseline, milestone = baseline), valid = 1, `submission_lower` status = proven, and N=14 is parsed correctly. `#print axioms` is within the allowlist [propext, Classical.choice, Quot.sound, Lean.ofReduceBool, Lean.trustCompiler]. Since this task allows `native_decide`, this fixture also checks that the `native_decide` path works. The same construction, converted to a sibling JSON certificate, is also valid=1 and reward=0 under the Solver checker (same score in both versions; see `../reference/CONCEPTS.md`).

Why not use the complete N=24 graph from the sibling version: exhaustive checking of its C(24,6)=134,596 six-element subsets exceeded the scoring sandbox's compilation budget (>40 minutes; see `../../PROVENANCE.md`). The oracle/sanity fixture checks that the scoring path works, rather than attempting a larger N.
