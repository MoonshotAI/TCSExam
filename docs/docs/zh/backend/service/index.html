部署 Online 判分服务 ​

本指南介绍服务配置、运行和平台适配器。 面向托管 Online Solver 判分的运维人员。

服务管理 HTTP 请求、判分会话、并行工作容器、反馈、归档和提交计数。 本地 Docker 主机可选择随附的 Docker 适配器，其他运行时可实现平台适配器接口。 运维人员负责提供执行主机、判分镜像和服务凭证。

本地 Docker 部署按配置生成流程操作。 HTTP 协议参考定义客户端请求和响应。

安装 ​

bash
python -m pip install -e '.[runtime,backend]'

配置 ​

手动配置服务时，复制示例并在服务环境中设置凭证：

bash
mkdir -p build
cp docs/backend/config.example.yaml build/backend.yaml
: "${TCSEXAM_TOKEN_ID:?Set the service identity}"
: "${TCSEXAM_TOKEN_SECRET:?Set the service secret}"
: "${TCSEXAM_ARCHIVE_TOKEN:?Set the verifier-only secret}"

从 config.example.yaml 开始；这是一个 Docker 示例，注释值展示默认设置。 敏感配置优先从环境读取（TCSEXAM_TOKEN_ID、TCSEXAM_TOKEN_SECRET、 TCSEXAM_ARCHIVE_TOKEN、TCSEXAM_WORKER_GROUP），并覆盖 YAML 值； 不要将真实令牌写入提交到仓库的文件。TCSEXAM_DOCKER_SOCKET 覆盖 Docker 套接字路径。

需特别注意 public_base_url：每个判分工作容器内的 agent 会连接 <public_base_url>/v1/tunnel/{app}，因此该地址必须能从判分工作容器访问。 默认值为 http://127.0.0.1:<port>，适用于随附测试适配器的本地测试。 Docker 示例显式使用 http://host.docker.internal:8420；当工作容器网络为非 host 模式时， Docker 适配器会拒绝容器回环 URL。参见 Docker 网络与主机要求。

归档凭证仅供验证器使用。启动服务前，确认工作容器能访问回调地址，且已准备好选定镜像。

启动与检查 ​

bash
tcsexam backend check --config build/backend.yaml   # validate config + load the adapter
tcsexam backend serve --config build/backend.yaml   # run the service

check 以 JSON 输出实际生效的配置，并加载已配置的适配器。 成功时退出码为 0，任何配置问题（包括 adapter 为空或适配器加载失败）均以 2 退出， 因此可以安全地接入部署流水线。serve 接受 --host / --port 覆盖选项。 python -m tcsexam.backend --config build/backend.yaml 是等价入口。

主凭证 auth.token_id 和 auth.token_secret 都必须是非空字符串。 本地测试若需禁用认证，应同时省略两项。仅配置一项或提供空值对会导致配置验证失败。 每个 additional_tokens 条目必须恰好包含两个非空字符串，且轮换凭证要求有主凭证对： 工作容器用主凭证连接隧道。验证会在加载 YAML 并应用环境覆盖后执行， 构建应用时再次执行；错误仅指出无效字段，不输出其值。 凭证比较支持 Unicode，对每对凭证的两个元素均使用常量时间字节比较。

只有显式提供 X-TCSEXAM-Client-Id 且实际生效的输入完全相同， 并发创建才会共用一个正在准备资源的会话。这些输入包括令牌身份、经验证的 run-id、 实际工作镜像（公开映射后）、上传文件名与内容、资源、生存时间、分片数和实例集。 省略默认资源或生存时间，等价于显式传入相同默认值。输入变化会创建独立会话； 不会悄然复用包含另一份上传内容的工作容器。

会话生存时间、工作容器启动和请求读取分别计时。 随附开发客户端请求 46800 秒（12 小时加一小时余量）；默认 max_ttl_seconds 也是 46800。 公开分片存储在整组就绪时开始服务侧生存时间，而平台工作容器生存时间从创建工作容器时开始。 因此启动耗时会占用部分平台余量。休眠释放工作容器，后续提交会准备新的工作容器； 提交历史会保留，服务侧生存时间在就绪时重新开始。 最终评测客户端创建独立会话，并保留各题 14400–28800 秒的生存时间。 降低 max_ttl_seconds 会限制两种客户端的请求，可能在预算用完前使活跃会话到期； 平台配置应同时容纳判分时间和启动余量。

ready_timeout_seconds 限制隧道连接等待时间。 无论创建单个工作容器还是分片组，工作容器 agent 均使用相同的启动预算，上限为 7200 秒。 逐镜像的 create_ready_timeout_seconds 传给平台适配器。 read_timeout_seconds（默认 7200）限制上游判分响应等待时间，并转发给每个工作容器 agent。 对于长时间判分请求，应增加读取超时及相应的分发超时； 只增加会话生存时间不会增加这些请求限额。

行为契约 ​

以下语义由题目客户端固定，并有测试覆盖；部署不得改变。

  • 提交在接受时计数一次。POST /v1/judge/sessions/{id}/submit 接受请求体后返回整数提交编号。 计数单位是转发层 /submit；向分片分发属于判分内部并行，不计提交次数。
  • /submit 的 HTTP 429 表示触及单会话提交次数上限，响应体为 {"error": "submission_cap_exceeded", "cap": ..., "used": ...}。 验证器将 429 解释为该上限，因此后端不得用它表示普通工作容器拥堵。
  • HTTP 503（error_class=transient）表示提交未被接受，可以重试。 它涵盖仍在准备资源的会话和全局容量不足的拒绝。 暂时性错误消息携带标记 "please try again"，题目侧重试匹配器会逐字匹配该标记。
  • HTTP 410（或 JSON 响应体中的 error_class=terminal）表示会话已永久销毁。
  • DELETE 销毁属于该会话的每个工作容器，并关闭服务侧每条反向隧道，包括所有分片。 使用已销毁会话的一次性应用名进行迟到重连会被以 404 拒绝；普通隧道断开仍允许重连。 会话状态变为 410 后，验证器仍能读取保留的归档以及创建/提交载荷历史。
  • 基础设施失败绝不产生有效零分。默认 min_ready_ratio: 1.0 下，部分资源准备失败会使整个会话失败； 失败的资源准备从未接受提交，因此不消耗调用方的提交预算。
  • 实例间共享一个时间池的题目必须以 n_shards=1 创建，即完整实例集放在一个工作容器中。 对时间池题分片会改变其判分语义。随附客户端已编码这一要求。
  • 归档凭证（X-TCSEXAM-Archive-Token）仅由验证器提供。 它控制归档和载荷下载、隐藏会话创建（包括省略 instance_set 的情况，默认值为 hidden）、 所有携带 judge_payload 的公开或隐藏创建操作，以及所有会话列表/核对查询。 凭证缺失、错误或未配置时，在创建任何工作容器或返回会话数据前即拒绝请求。 归档和载荷端点保留统一 404 契约；创建和列表入口返回 403。
  • 不携带 judge_payload 的公开自测会话（instance_set=public）仅需要服务令牌对。 其状态、提交和结果轮询路径不使用归档凭证。 创建公开会话要求精确匹配的 public_image_map 条目，并将仅含公开数据的映射值用作会话和工作容器镜像。 映射为空或请求镜像未注册时，在注册会话或创建工作容器前返回 403；不会回退到原始镜像。 创建隐藏会话从不应用此映射。公开会话写入日志以保留历史，但不计入提交次数上限。
  • 会话属于创建它的运行。实际生效的 run-id（经身份认证中间件验证的 X-TCSEXAM-Run-Id） 存储在会话中并写入日志，因此在 DELETE 和服务重启后仍保留。 每个会话级端点——状态、转发（/submit、/submissions 和任何转发的尾部路径）、 DELETE、归档、三个载荷端点，以及 ?session_ids= 核对查询——仅服务于 run-id 与会话所有者匹配的请求。 不匹配时的响应与未知会话 id 完全相同：统一 404（unknown judge session {sid}）， 绝不返回 401/403 或已销毁状态的 410 形式，因此该检查不会泄漏会话是否存在； 在 ?session_ids= 响应中，不匹配的 sid 返回 present=false 且不提供计数。 普通列表和 ?client_ip= 诊断查询返回的会话遵循相同归属过滤，包括保留的已销毁会话； 诊断查询总数仅包含可见行。对未知会话执行 DELETE 与错误运行的请求返回相同 404， 而已知且已释放会话的所有者重复 DELETE 时仍返回 200 和 stopped=false，日志重放后亦如此。 /v1/status 路由仍提供含全局统计的服务级运维视图。 创建时未携带 run-id 的会话无所有者且不受限制（从不发送 run-id 的本地和旧版调用方仍可使用）。 创建去重键也包括 run-id：即使发送相同的 X-TCSEXAM-Client-Id，两个运行也绝不共用正在准备资源的会话， 同一运行的并发重试仍可共用。

安全边界 ​

  • 需要身份认证的部署应使用服务令牌对，并通过环境注入。真实凭证存放于源码仓库之外。
  • 归档令牌只交给验证器。它授权隐藏会话创建、会话核对和归档访问； 不得进入模型环境、工作容器和提交转发接口。
  • Run-Id 是调用方提供的尝试标签。对于彼此不信任的调用方， 除共享令牌服务外，还需为每次尝试提供独立认证的凭证或等效授权层。
  • 公开会话映射到仅含公开数据的镜像。按公开镜像指南审查所有保留镜像层； 镜像内容分离后再选择公开判分模式。
  • Docker 套接字仅交给后端进程。它能控制主机，必须保留在模型容器和判分工作容器之外。
  • 平台凭证保留在适配器配置内，不得出现在日志、工作容器环境和异常消息中。

故障排查 ​

读法说明：根据现象或部署条件查看相应处理方法。

现象或部署条件处理方法
Docker 准入或配额检查失败按 Docker 主机指南检查实际生效的 CPU、内存和配置的存储配额。
服务停止后仍有工作容器残留重启服务以恢复其管理的工作容器，或检查并仅删除确认归属的容器。到期处理在后端进程内运行。
自定义或旧版工作程序在 run_id_mode=required 时收到 HTTP 400隧道连接携带其所属的 X-TCSEXAM-Run-Id。混合版本升级期间保持 warn，启用 required 前先更新工作容器 agent。
长时间评测丢失会话在 max_ttl_seconds 中允许所请求的生存时间和启动余量；同时检查配置参考中的请求读取超时。
选择 local-test仅用于后端开发测试。其工作环境是本地临时目录，无资源限制或隔离。

worker.name属性 str平台侧标识，仅用于日志
worker.deleteasync () -> None销毁工作容器；幂等，尽力执行（工作容器自身 TTL 是最终兜底限制）
worker.resources可选属性 WorkerResources创建时的资源。非必需：BasePlatformAdapter 优先用它统计 long_lived_memory_mb，否则回退到自身 create_sandbox 记录的资源

每个实现必须遵循的行为规则：

  • 按请求原样提供镜像和资源。平台无法提供时，抛出明确错误。 静默启动较小规格的工作容器违反契约：判分运行假定资源与声明一致。
  • 错误按类名分类。errors.NON_TRANSIENT_ERROR_NAMES 中的名称 （AuthenticationError、PermissionDeniedError、InvalidArgumentError、 InsufficientCreditsError、JudgeBootError）从不重试； 其他异常均视为暂时性错误，以指数退避重试。 ValueError 始终视为非暂时性错误（调用方程序错误）。
  • stop_app 和 worker.delete() 均幂等。
  • 清理范围有限：仅销毁适配器自己创建的资源，绝不执行整个账号范围的清理。
  • 取消创建不能遗留已创建一部分的工作容器。
  • 平台凭证保存在适配器自身配置中，不得出现在日志、工作容器环境变量或异常消息中， 因为异常文本会传播到题目客户端。

继承 BasePlatformAdapter 可获得受创建并发控制的暂时性错误重试循环、 长驻资源表，以及支持恢复 agent.log 尾部的幂等 stop_app； 此时只需实现 _create_worker，即面向具体平台的一次创建尝试。

加载方式：adapter: docker 选择 Docker 指南描述的随附 Docker 实现。 其他平台将 adapter 设为 module:factory。 工厂被导入后，若接受一个位置参数，则用已加载的 Config 调用；否则不传参数。 返回结果会按上述完整接口检查。adapter 为空时，启动以 ConfigurationError 失败， 服务绝不静默回退到测试替代实现。显式值 local-test 选择随附的本地进程测试适配器 （仅用于测试；其工作环境是服务主机上的临时目录，无隔离或资源限制）。

使用随附契约测试套件自检任意适配器：

bash
python -m tcsexam.backend.contracttest --adapter mypackage.cloud:make_adapter --config config.yaml \
    --image registry.example.com/your-judge:1 --profile your-profile
python -m tcsexam.backend.contracttest --adapter docker --config config.yaml \
    --image registry.example.com/your-judge:1 --profile local
python -m tcsexam.backend.contracttest --adapter local-test   # exercise the test double

套件为每项检查输出一行；全部通过时退出码为 0，任一检查失败为 1，适配器无法加载为 2。 它通过适配器创建真实资源，并销毁自己创建的每个工作容器，因此应指向测试环境。 检查与具体平台无关：创建严格遵循请求、工作容器身份唯一、文件准备、状态诊断、 命令启动、内存统计、幂等停止/删除、创建失败清理，以及限定范围的清理。

--image 和 --profile 决定检查传给 create_sandbox 的参数。 传入可用镜像以及平台预期的 profile。默认值 （registry.example.com/contract-judge:1 / contract-profile）是供本地测试适配器使用的示例。
